Chat Attachment Manager UNIVERSAL 1.2
=====================================

هدف این نسخه
------------
این نسخه دیگر فقط برای LiveChat یا فایل *.txt ساخته نشده است.
Scanner فایل‌ها را از روی محتوای متنی تشخیص می‌دهد و اگر فایل قابل‌خواندنِ متنی باشد، آن را بررسی می‌کند.

نمونه فرمت‌های قابل قبول:
- TXT
- JSON / JSONL
- CSV / TSV
- LOG
- HTML / HTM
- XML
- MD / Markdown
- YAML/YML و سایر فایل‌های متنی
- فایل متنی بدون پسوند

پسوند فقط کمک‌کننده نیست؛ تشخیص اولیه بر اساس بایت‌های واقعی فایل است.
فایل‌های باینری مثل JPG/ZIP/EXE به عنوان فایل منبع اسکن نمی‌شوند.

فرمت گفتگو
-----------
Scanner به فرمت خاصی وابسته نیست.
این ساختارها را می‌شناسد:
- CHAT #... + Chat ID
- RECORD #... + Conversation ID
- [FILE] / [IMAGE] / [PHOTO] / [VIDEO] / [AUDIO] / [DOCUMENT]
- [ATTACHMENT] { JSON ... }
- URL معمولی داخل هر متن/JSON/HTML/XML/CSV/LOG/MD

برای Tawk.to ساختار زیر مستقیماً پشتیبانی می‌شود:
[ATTACHMENT] {"type":"file","content":{"file":{"name":"...","url":"...","mimeType":"..."}}}

URLهای Escape شده
-----------------
Scanner این‌ها را نرمال می‌کند:
- https://example.com/file.pdf
- https:\/\/example.com\/file.pdf
- \u002F و سایر JSON unicode escapes در URL
- &amp; و HTML entities

تشخیص نهایی فایل در Downloader
-------------------------------
Scanner فقط کاندیدها و URLها را جمع می‌کند.
Downloader برای هر URL پاسخ واقعی HTTP را می‌بیند و از این اطلاعات استفاده می‌کند:
- Content-Type
- Content-Disposition / filename / filename*
- Redirect و URL نهایی ResponseUri
- نام فایل صریح داخل Export
- پسوند URL اولیه یا نهایی

صفحه عادی HTML بدون نشانه فایل دانلود نمی‌شود و در urls_skipped_as_nonfiles.csv ثبت می‌شود.
URL بدون پسوند اگر مثلاً Content-Type آن image/jpeg، application/pdf، video/mp4، text/plain، application/json و ... باشد، می‌تواند به عنوان فایل ذخیره شود.

نکته مهم درباره تعداد URLها
---------------------------
در GUI قسمت «کل URLها» ممکن است از تعداد فایل واقعی خیلی بیشتر باشد.
دلیل: همه URLها یک بار با HTTP بررسی می‌شوند تا فایل‌های بدون پسوند از دست نروند.
URLهایی که فایل نیستند فقط یک بار بررسی می‌شوند و نتیجه SkippedNonFile در checkpoint ذخیره می‌شود.

Resume و Cache
--------------
نتیجه هر فایل منبع جداگانه Cache می‌شود.
اگر Scanner قطع شود، فایل‌های منبع تمام‌شده دوباره اسکن نمی‌شوند.
Downloader نیز نتیجه هر URL را در download_state.jsonl ذخیره می‌کند.

فایل‌های خروجی مهم
------------------
files\                         فایل‌های دانلودشده
all_urls_inventory.csv         همه URLها و اطلاعات منبع
source_files_detected.csv      فایل‌هایی که Scanner به عنوان متن تشخیص داده
attachments_index.csv          فایل‌های دانلودشده
attachments_failed.csv         خطاهای دانلود
urls_skipped_as_nonfiles.csv   URLهایی که پاسخ HTTP نشان داده فایل نیستند
_chat_attachment_manager\      Cache، Resume، Engine و وضعیت پروژه

شروع برای کاربر مبتدی
---------------------
1) ZIP را کامل Extract کنید.
2) OPEN_MANAGER.cmd را اجرا کنید.
3) «پروژه جدید» را بزنید.
4) پوشه فایل‌های منبع را انتخاب کنید.
5) پوشه خروجی را انتخاب کنید.
6) اگر فایل‌های منبع داخل زیرپوشه‌ها هم هستند، گزینه زیرپوشه‌ها را فعال کنید.
7) «شروع / ادامه» را بزنید.

Preflight قبل از اسکن کامل، Scanner و منطق Downloader را بدون درخواست شبکه تست می‌کند.

رفتار شبکه
----------
- دانلودها ترتیبی هستند، نه ده‌ها دانلود هم‌زمان.
- HTTP 429 و Retry-After رعایت می‌شود.
- cooldown برای هر Host جداست؛ محدود شدن یک Host بقیه Hostها را متوقف نمی‌کند.
- Redirect دنبال می‌شود.
- فایل نیمه‌کاره در صورت پشتیبانی سرور Resume می‌شود.

نسخه Engine: UNIVERSAL-1.2


بهینه‌سازی Preflight
====================
تست اولیه حداکثر ۳ فایل منبع و حداکثر ۶۰۰۰ خط از هر فایل را می‌خواند.
بنابراین اگر فقط ۱ یا ۲ فایل بسیار بزرگ دارید، تست اولیه کل فایل‌ها را بیهوده دوباره اسکن نمی‌کند.

تشخیص فایل متنی
===============
نام/پسوند فایل منبع شرط نیست. محتوا بررسی می‌شود.
امضاهای باینری رایج مثل PDF، JPG/PNG/GIF، ZIP/RAR/7z، EXE، gzip، OLE، ELF، RIFF و MP4/MOV
قبل از اسکن رد می‌شوند تا فایل باینری اشتباهی به عنوان آرشیو متنی خوانده نشود.


UNIVERSAL 1.2 — روش ذخیره فایل‌ها
=================================

در بخش «پروژه» دو انتخاب جدید وجود دارد:

1) پوشه فقط برای چت‌هایی که واقعاً فایل دانلودشده دارند (پیشنهادی)
------------------------------------------------------------------
هیچ پوشه‌ای برای چت بدون فایل ساخته نمی‌شود.
حتی اگر لینک فایل خراب باشد یا دانلود نصفه بماند، پوشه چت ساخته نمی‌شود.
فایل نیمه‌کاره داخل پوشه مدیریتی partials نگهداری می‌شود.

نمونه:
files\
  RECORD_000245\
    01_passport.jpg
    02_bank-statement.pdf
  CHAT_013001\
    01_report.pdf

2) همه فایل‌ها در یک پوشه + کد چت در نام
-----------------------------------------
هیچ پوشه جداگانه‌ای برای چت ساخته نمی‌شود.

نمونه:
files\
  RECORD_000245_01_passport.jpg
  RECORD_000245_02_bank-statement.pdf
  CHAT_013001_01_report.pdf

شماره فایل فقط برای فایل‌هایی مصرف می‌شود که پاسخ HTTP نشان داده واقعاً فایل هستند.
URLهای معمولی که صفحه وب باشند شماره نمی‌گیرند.

برای Resume پایدار، برنامه فایل storage_map.jsonl را در پوشه
_chat_attachment_manager نگه می‌دارد. این فایل را در پروژه فعال پاک نکنید.

روش ذخیره‌سازی بعد از شروع دانلود پروژه قفل می‌شود تا دو ساختار با هم قاطی نشوند.
برای استفاده از روش دیگر، پروژه جدید با Output جدا بسازید.


HOTFIX UNIVERSAL 1.2.1 — رفع حلقه NETWORK_PAUSE
=================================================

مشکل نسخه 1.2:
اگر 5 URL پشت‌سرهم خطای شبکه/DNS/TLS می‌دادند، Downloader با NETWORK_PAUSE خارج می‌شد.
Supervisor یک دقیقه بعد آن را از نو اجرا می‌کرد و شمارنده تلاش‌های همان URLها صفر می‌شد.
در نتیجه چند URL خراب می‌توانستند برنامه را در حلقه دائمی نگه دارند.

نسخه 1.2.1:
- خطای شبکه فقط Host همان URL را وارد cooldown می‌کند.
- Hostهای دیگر بدون توقف ادامه پیدا می‌کنند.
- اگر همه URLهای باقی‌مانده مربوط به Hostهای cooldown باشند، Downloader فقط تا نزدیک‌ترین پایان cooldown صبر می‌کند.
- هر URL حداکثر تعداد تلاش همان دور را طی می‌کند؛ سپس TransientFailure ثبت می‌شود و برنامه سراغ بقیه می‌رود.
- دیگر برای خطاهای عادی شبکه کل Downloader با NETWORK_PAUSE بسته نمی‌شود.
- دانلودها، checkpoint، inventory و اسکن پروژه قبلی قابل ادامه هستند و نباید پاک شوند.


UNIVERSAL 1.2.2 FASTSCAN
========================
این نسخه کندی Scanner عمومی روی آرشیوهای بزرگ LiveChat را اصلاح می‌کند.

تغییر اصلی:
- قبلاً URL decoder / HtmlDecode / Regexهای URL روی تقریباً هر خط اجرا می‌شدند.
- حالا پردازش سنگین URL فقط وقتی اجرا می‌شود که خود خط واقعاً شامل http باشد.
- https:\/\/ در JSON نیز همچنان شامل http است و از دست نمی‌رود.
- [ATTACHMENT] JSON فقط روی خطوطی که واقعاً با [ATTACHMENT] شروع می‌شوند Parse می‌شود.
- [FILE]/[IMAGE]/... فقط روی خطوط marker بررسی می‌شوند.
- جستجوی conversationId/chatId در JSON فقط روی خطوطی با کلیدهای محتمل اجرا می‌شود.
- بروزرسانی دیسکی وضعیت از هر 1 ثانیه به هر 2 ثانیه کاهش یافت تا I/O مزاحم اسکن نشود.

Cache سازگار است:
فایل‌های منبعی که نسخه قبلی کامل اسکن و checkpoint کرده، در پروژه موجود دوباره اسکن نمی‌شوند.
فقط فایل منبع ناتمام دوباره از ابتدای همان فایل خوانده می‌شود.
